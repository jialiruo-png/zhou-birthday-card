# 桌面 Stage 版内容同步设计

## 目标

在保留桌面 Stage 版自动放映体验的前提下，将当前手机端已确认的内容同步到桌面端，并将两端更新部署到现有服务器。

## 同步范围

- 手机端与桌面端祝福数据保持一致，共 31 条，并包含甘华粱和韩飞的祝福。
- 韩飞显示为“2020 级博士”，排在魏珂之后、梁玉虎之前；手机端 `wishOrder` 使用相同顺序。
- 桌面端祝福顺序与手机端当前顺序一致。
- 桌面端师生故事与手机端保持一致，共 6 条，并包含马一源的故事。
- 桌面端成果长卷继续自动滚动，内容顺序保持为著作、论文、科研项目、荣誉奖励、咨政成果。
- 手机端现有成果 tab 修复继续保留，不把 tab 交互移植到桌面端。

## 实现方式

调整 `script.js`、`stage.js` 中的祝福数据与手机端 `wishOrder`，并把 `index.html` 的初始祝福总数更新为 31。桌面端的时间轴、自动翻页、自动滚动、键盘控制和视觉布局保持不变。手机端继续使用 `index.html` 与 `script.js`，桌面端继续使用 `stage.html`、`stage.css` 与 `stage.js`。

## 数据流

`stageData.wishes` 生成逐条祝福场景，`stageData.stories` 生成逐条故事场景，`window.achievementData` 生成自动滚动成果长卷。同步后的数据进入既有 `buildTimeline()`，不新增运行时依赖。

## 检查与部署

- 不修改现有脚本资源版本。
- 部署前检查 JavaScript 语法、祝福数量和排序；部署后校验服务器文件哈希与线上数据。

## 验收标准

- 手机端与桌面端祝福均为 31 条。
- 魏珂之后紧接韩飞，韩飞之后紧接梁玉虎，韩飞身份显示“2020 级博士”且正文完整。
- 手机端 `wishOrder` 与两端祝福展示顺序一致。
- 桌面端故事场景共 6 条，包含马一源。
- 桌面端成果长卷按既定五类顺序自动滚动，页面无可点击成果 tab。
- 线上手机入口和 `stage.html` 均加载最新版本且无 JavaScript 语法错误。
