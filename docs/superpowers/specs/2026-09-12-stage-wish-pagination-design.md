# Stage 全员祝福自动分页设计

## 目标

- 全员祝福的正文统一使用同一个放大后的字号，不再因为内容长短而缩小字体。
- 任意长度的祝福都必须完整展示，不能被卡片边界或署名遮挡。
- 长祝福自动拆成连续的 Stage 场景页，自动播放和上一页/下一页操作都能按分页顺序工作。

## 方案

在进入放映前，根据当前浏览器实际可用的卡片尺寸和正文样式进行分页测量。测量器复用 `.wish-stage-card` 和正文的实际 CSS，将祝福按段落、句子和字符逐级拆分，直到每一页的正文在固定字号下都能完整放入卡片；最后一页额外预留署名区域。这样分页结果会适配窗口尺寸和全屏尺寸，不依赖固定字符数。

时间线会把一条长祝福展开为多个连续的 `wish` 场景，每页保留姓名与身份信息，页码沿用现有 Stage 总页数显示。每页停留时间根据该页文字量计算并设置上下限，保证短页不会一闪而过、长页有足够阅读时间。重新开始放映时重新测量；窗口尺寸变化后，下一次进入或重新开始时重新生成分页结果。

## 组件变更

- `stage.js`
  - 新增基于真实 DOM 尺寸的祝福分页器。
  - `buildTimeline()` 在测量完成后展开长祝福页。
  - `renderWish()` 渲染当前页内容及页级署名信息。
  - 删除会缩小长正文的自适应字号逻辑，保证所有祝福正文字号一致。
- `stage.css`
  - 全员祝福正文在当前基础上再放大一档。
  - 保持卡片固定安全区域和隐藏溢出；分页器确保隐藏溢出前内容已经拆页。

## 验收标准

- 普通祝福与长祝福每一页正文使用完全相同的计算字号。
- 最长祝福自动分成多页，每一页正文和署名均不被裁切或遮挡。
- 自动播放、暂停、上一页、下一页、重新开始的顺序和页码正确。
- 切换窗口尺寸或全屏后重新开始，分页能根据新的可用空间重新计算。
- `node --check stage.js` 和 `git diff --check` 通过。
